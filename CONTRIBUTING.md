# Как участвовать

Спасибо, что заглянули. Проект небольшой и личный, поэтому правила короткие.

## Прежде чем писать код

Если правка больше пары строк — заведите
[issue](https://github.com/Karavang/Leser/issues) и опишите, что хотите сделать.
Так меньше шансов написать то, что не примут: у проекта есть вещи, которые
**не делаются осознанно**, и они перечислены в [TODO.md](TODO.md).

Баг-репорт полезнее всего, когда в нём есть книга (или ссылка на неё), на которой
воспроизводится: половина проблем здесь — про конкретный файл конкретного формата.

## Проверки

PR не пройдёт CI, если не проходят эти команды:

```sh
cd api      && cargo fmt --check && cargo clippy --all-targets -- -D warnings && cargo test
cd frontend && npm run lint && npm test && npm run build
```

Строки интерфейса живут в `frontend/src/i18n.js` — русская и английская рядом.
`npm test` проверяет, что ключи не разошлись, поэтому новая надпись едет сразу
на двух языках. Сообщение об ошибке с бэка — тоже: `AppError::bad(ru, en)`.

Новая нетривиальная логика приезжает с одной проверкой на неё — не набором
тестов на каждую функцию, а самым маленьким, что упадёт, если логика сломается.
Смотрите, как сделано в `api/src/reader.rs`.

## Стиль

- **Комментарии объясняют «почему», а не «что».** Что делает код, видно из кода.
  Ценно то, чего в нём не видно: почему выбрано это, а не очевидное соседнее.
- **Сознательное упрощение помечается** комментарием `ponytail:` — с потолком
  и путём наверх. Не «здесь плохо», а «здесь достаточно, а вот когда перестанет
  хватать и что делать тогда».
- **Комментарии и документация — по-русски**, имена в коде — по-английски.
- Форматирование делают `cargo fmt` и eslint, руками спорить с ними не нужно.

## Что не стоит присылать

- Новые зависимости ради того, что решается несколькими строками. Прежде чем
  добавлять крейт или пакет, посмотрите, нет ли этого в стандартной библиотеке,
  в возможностях платформы (CSS, `<dialog>`, `<details>`) или в том, что уже
  установлено.
- Абстракции «на будущее»: интерфейс с одной реализацией, фабрика ради одного
  продукта, настройка для значения, которое никогда не менялось.
- Массовое переформатирование и переименования вперемешку с правкой по существу —
  в таком PR не видно самой правки.

## Про права на код

Отправляя pull request, вы соглашаетесь, что ваш вклад распространяется
на условиях [AGPL-3.0](LICENSE) **и** что автор проекта может распространять его
также на других условиях, включая коммерческую лицензию.

Это нужно, чтобы у проекта оставалась возможность двойного лицензирования:
ядро остаётся открытым, а платные модули, если появятся, не упираются в чужие
авторские права. Если такое условие вам не подходит — напишите в issue, обсудим
до того, как вы потратите время на код.
