## Запуск

```sh
cp .env.example .env                     # JWT_SECRET: openssl rand -hex 32
docker compose up --build
```

Фронт на http://localhost:8081, API на http://localhost:4444, Postgres на 5432.
Миграции схемы применяются при старте api.

Фронт зовёт бэкенд по относительному `/api/*`, его проксирует nginx контейнера —
один origin, CORS не участвует. Для `npm run dev` (порт 5173) то же делает
vite-прокси, цель переопределяется через `VITE_API_TARGET`.

## Адреса

| путь | что |
|---|---|
| `/` | библиотека |
| `/login` | вход и регистрация |
| `/me` | профиль, настройки, удаление аккаунта |
| `/book/{uuid}.{ext}` | читалка, одна на все форматы |

Всё, кроме `/login`, за проверкой токена: нет токена — переход на `/login`.
Раньше экраны переключались флагами в состоянии, и выход из аккаунта оставлял
смонтированной страницу, которой уже нечего показать, — пустой фон вместо формы
входа. Неизвестный адрес ведёт в библиотеку, а не в ошибку.

## Читалка

Читалка своя и одна на все форматы. Формат разбирает сервер (`GET /api/read`,
подробности в [api/README.md](api/README.md#читалка)), фронт получает главы
с готовой разметкой — и epub, fb2 и `.rda` открываются одинаково. Разбор
происходит один раз, при загрузке книги: библиотека только пополняется, файл
не меняется, и разбирать его заново на каждое открытие незачем.

Страницы верстает браузер: `.readerPages` ограничена высотой экрана и разложена
в колонки, поэтому лишний текст уходит вправо, а «перелистнуть» — это прокрутить
ровно на ширину окна. Своей разбивки на страницы нет: колонки CSS умеет сам,
и в них попадают ровно целые строки. На широком экране колонок две — разворот,
как в бумажной книге; строка через весь монитор нечитаема.

Есть шрифт (семь размеров), три темы, оглавление, полоса прокрутки по книге
и переносы по языку книги. Листается стрелками, пробелом, Home/End, кнопками
по краям и свайпом; Esc закрывает.

Ссылки внутри книги — оглавление в аннотации, сноски — работают: читалка сама
считает, на какой странице лежит цель, и предлагает вернуться туда, откуда
ушли. Обычный переход по якорю здесь не годится, он прокрутил бы колонки мимо
границ страниц.

Место в книге хранится долей прочитанного, а не номером страницы: страницы
разные при разном шрифте и размере окна, доля — одна и та же. Старые закладки
от прежней читалки (`epubcfi(...)`) числом не притворяются и просто
игнорируются — такая книга откроется с начала.

Прежде тут были две читалки: `react-reader` для epub и своя для fb2, которая
показывала всю книгу одной простынёй `textContent` — без абзацев, глав и
закладки. Зависимость убрана: бандл 688 → 323 КБ, потому что вместе с ней
уезжает epub.js с распаковкой zip в браузере.

## Прод

Конфиг сервера лежит в [deploy/nginx.prod.conf](deploy/nginx.prod.conf) — оттуда
его и катать, чтобы правки ходили через git. Главное: `location /api/` обязан
быть в том же server-блоке, что и статика, иначе фронт не найдёт бэкенд.

Образы обоих сервисов многостадийные: в рантайм едет только результат сборки —
у api это один бинарник на distroless (ни shell, ни cargo), у фронта `dist`
на nginx (без node). Отсюда и вес образа, и то, что в проде не лежат исходники.

## CI

[.github/workflows/ci.yml](.github/workflows/ci.yml) на каждый push и PR гоняет
три независимые джобы параллельно — упавший фронт не скрывает результат по бэку:

| джоба | что делает |
|---|---|
| `api` | `cargo fmt --check`, `cargo clippy -D warnings`, `cargo test` |
| `frontend` | `npm ci`, `npm run lint`, `npm run build` |
| `docker` | `docker compose build` — ловит сломанный Dockerfile |

Образы никуда не пушатся. Понадобится деплой — отдельная джоба с
`needs: [api, frontend]`, login в registry и push с тегом `${{ github.sha }}`.

Те же проверки локально:

```sh
cd api      && cargo fmt --check && cargo clippy --all-targets -- -D warnings && cargo test
cd frontend && npm run lint && npm run build
```
