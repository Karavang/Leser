# leser-api

Бэкенд Leser: Rust (axum) + Postgres. Заменил старый Node/Express/Mongo
([Karavang/LeserMashine](https://github.com/Karavang/LeserMashine), из репозитория удалён).
Контракт API не менялся: во `frontend/` поменялся только базовый адрес —
абсолютный `https://api.leser.cloud` стал относительным `/api`.

## Запуск

Через `compose.yml` в корне репозитория — там же поднимается фронт и Postgres.
Только бэкенд: `docker compose up --build db api`.

Локально без Docker: `docker compose up db`, затем `cargo run` с переменными из
`../.env`. Миграции схемы применяются сами при старте.

## Переменные

| Переменная | Зачем |
|---|---|
| `DATABASE_URL` | строка подключения к Postgres |
| `JWT_SECRET` | подпись токенов, `openssl rand -hex 32` |
| `CORS_ORIGINS` | разрешённые origin через запятую; контейнерный фронт идёт через nginx одного origin, так что нужен только для vite dev-сервера |
| `PORT` | по умолчанию 4444 |
| `GITHUB_TOKEN` | необязательный; без него источник GitHub выключается, остальные работают |

## Эндпоинты

| Метод | Путь | |
|---|---|---|
| POST | `/registration` | `{username,email,password}` → пользователь + JWT |
| POST | `/login` | `{email,password}` → пользователь + JWT |
| GET | `/logout` | no-op, токен stateless |
| DELETE | `/account` | удаляет юзера из токена вместе с его закладками |
| GET | `/getAll?q=` | книги; `q` ищет по названию, автору и серии |
| GET | `/searchSources?q=` | поиск по внешним источникам, только ссылки |
| POST | `/import` | `{url, pageUrl}` — забрать книгу из источника в библиотеку |
| GET | `/booksInRead` | книги с закладкой текущего юзера |
| GET | `/downloadOne/{id}.{ext}` | файл книги телом ответа |
| GET | `/read/{id}.{ext}` | книга для читалки: главы с разметкой, одним ответом |
| POST | `/putNewOne` | multipart `file`, epub/fb2, до 64 МБ, метаданные чистятся |
| DELETE | `/deleteOne/{id}.{ext}` | своя книга, админ — любая |
| POST | `/pageWasFlipped` | `{filename,page}`, upsert закладки |
| POST | `/myBooks/{id}.{ext}` | отложить книгу себе |
| DELETE | `/myBooks/{id}.{ext}` | убрать со своей полки |
| GET | `/health` | для healthcheck |

Всё, кроме `/registration`, `/login`, `/health`, требует `Authorization: Bearer <jwt>`.

## Что изменилось по сравнению с Node-версией

- Пароли — argon2 вместо открытого текста.
- Файлы книг лежат в Postgres (`book_files.data`), S3 не используется. `/downloadOne` отдаёт байты одним ответом; локальный кэш `timeBooks/` и раздача статики убраны — там был path traversal.
- Загрузка книги — одна транзакция: строки без файла и файла без строки быть не может.
- `users.pages[]` → таблица `reading_progress`, переворот страницы это один upsert.
- JWT проверяется без запроса в БД.
- Права на удаление проверяет SQL (`owner_id` или админ), раньше не проверялись вообще.
- В каждой книге приходят `source` (кто принёс или откуда), `mine` (лежит ли
  у меня на полке) и `canDelete` — права считает сервер, фронт только не рисует
  заведомо запрещённую кнопку.
  У книг, чей владелец удалил аккаунт, источник становится прочерком: сама книга остаётся
  в библиотеке, `books.owner_id` уходит в `null` по `on delete set null`.
- epub/fb2 разбираются в памяти, без записи во временный файл.
- `/synchronizeBooks` удалён: источник правды один — Postgres.
- `pdf` не поддерживается — старый бэк его тоже отклонял при загрузке.

## Поиск

`GET /getAll?q=…` ищет по названию, автору и серии сразу. Книга подходит, если
совпало **каждое** слово запроса — в любом из трёх полей.

Разбор запроса в `src/search.rs`, сравнение делает Postgres. Четыре слоя, каждый
закрывает то, что не умеет предыдущий:

| слой | что чинит | пример |
|---|---|---|
| разбиение на слова | слово из названия и слово из автора лежат в разных полях | `карнеги друзей` |
| `ilike` | регистр, любой язык — свёртку даёт коллация базы (`en_US.utf8`) | `ГАРРИ`, `PRATCHETT`, `MANTOLU` |
| транслитерация латиница → кириллица | русское название, набранное латиницей | `kak zavoevat` |
| раскладка, оба направления | забыли переключить язык | `rfhytub` → Карнеги, `зкфесруее` → Pratchett |
| триграммы (`word_similarity` ≥ 0.5) | словоформы и опечатки | `завоевать` ≈ `завоевывать`, `гари потер` |

Прочтения запроса (как набрано, транслитерация, две раскладки) складываются
в набор и схлопываются по совпадению — у кириллического запроса их два, у
чисто цифрового один. Книга подходит, если целиком совпало любое прочтение.
Прочтения не комбинируются между собой: раскладка не подаётся на вход
транслитерации, такой запрос — уже две опечатки подряд.

Триграммы тут не роскошь: `завоевать` не подстрока `завоевывать`, и русский
стеммер их тоже не сводит (`завоева` против `завоевыва`) — полнотекстовый поиск
этот случай не закрыл бы. Слова короче 4 символов ищутся только точным
вхождением: короткое слово похоже на слишком многое.

`%` и `_` экранируются: `q=50%` находит книгу с процентом в названии, а не всю
библиотеку.

Серия берётся из файла при загрузке — `<sequence name="…">` в fb2,
`belongs-to-collection` или `calibre:series` в epub.

Индекса под поиск нет: `ilike '%q%'` открыт с обеих сторон, btree на нём
бесполезен, а на нынешней библиотеке скан по трём полям — микросекунды.
Путь наверх, когда книг станет тысячи, записан в `migrations/0002_series.sql`.

## Внешние источники

Своя библиотека приоритетнее: фронт сначала показывает её (`/getAll`), а за
внешним идёт вторым запросом (`/searchSources`). Чужая сеть медленнее и может
не ответить — своя выдача этого ждать не должна.

| источник | ключ | что даёт |
|---|---|---|
| Project Gutenberg (gutendex.com) | не нужен | общественное достояние, прямые ссылки на epub |
| GitHub (`/search/code`) | `GITHUB_TOKEN` | файлы книг в публичных репозиториях |

Источники опрашиваются параллельно, и упавший даёт ноль своих книг, а не ошибку
всего поиска. GitHub без токена отвечает 401, поэтому без `GITHUB_TOKEN` он
просто выключается — в лог при старте пишется, что выключен.

`/searchSources` возвращает только ссылки. Книга попадает в библиотеку лишь
после явного `/import`, и там же — **защита от SSRF**: сервер скачивает адрес,
присланный клиентом, поэтому ходить можно только по `https` и только на хосты
из `ALLOWED_HOSTS`, причём проверяется каждый переход по редиректу
(gutenberg.org редиректит сам), а не только первый адрес. Размер ограничен тем
же потолком в 64 МБ — и по заявленному `Content-Length`, и по фактически
полученному.

Метаданные импортированной книги берутся **из самого файла**, а не из того, что
показал источник: `/import` идёт через ту же `store_book`, что и загрузка с
диска, — тот же разбор, та же чистка, та же транзакция. Внешняя книга не может
попасть в базу по более слабым правилам, чем своя.

## Читалка

`GET /read/{id}.{ext}` отдаёт книгу в одном виде независимо от формата:

```json
{ "title": "…", "author": "…", "lang": "ru",
  "chapters": [ { "title": "Глава 1", "html": "<p>…</p>" } ] }
```

Разбор формата стоит здесь, а не в браузере. Иначе на каждый формат нужна своя
читалка (а под epub ещё и распаковка zip в js), и выглядят они по-разному.
Так читалка на фронте одна и про форматы не знает вовсе.

Книга едет целиком одним ответом: тогда оглавление, проценты и переход по главам
не требуют новых запросов. Ответ помечен `immutable` — второе открытие книги
до сервера не доходит вовсе.

**Разбирается книга один раз — при загрузке.** Библиотека только пополняется,
файл книги не меняется никогда (на каждую загрузку новый id), значит и результат
разбора не меняется: распаковывать zip и обходить xml на каждое открытие незачем.
`store_book` кладёт готовый документ в `book_docs`, `/read` его оттуда и отдаёт —
строкой, как есть, без круга через serde. Первое открытие книги, загруженной
до этой таблицы, собирает документ на лету и запоминает: если разбор поумнеет,
достаточно `delete from book_docs`, и книги пересоберутся сами.

Оригинал при этом никуда не девается — с него отдаётся `/downloadOne`, и из него
документ пересобирается. Место: разобранная книга примерно того же размера,
что и файл.

Отсюда же следует, что книга, из которой не достать ни строчки текста,
**не принимается при загрузке**: читать её всё равно нечем, и сказать об этом
сразу честнее, чем оставить в библиотеке книгу, которая не открывается.

**Разметка на выходе безопасна по построению.** Фронт вставляет её через
`dangerouslySetInnerHTML`, поэтому из файла в неё не попадает ничего: теги
берутся только из таблиц `fb2_rule`/`html_rule` в `src/reader.rs`, атрибуты
пишет сервер сам, весь текст экранируется, `<script>` и `<style>` выкидываются
вместе с содержимым. Атрибуты исходника не читаются вообще, кроме ссылки
на картинку, — чужой `onclick=` до выхода не доезжает. Это проверяет тест
`hostile_markup_is_neutralised`.

Картинки уезжают в том же ответе, `data:`-ссылками: отдельная выдача картинки
потребовала бы токена прямо в `<img src>`, а его туда не положишь. Потолки:
12 МБ текста и 4 МБ картинок на книгу, дальше разметка просто обрывается.

Заголовок главы берётся из оглавления epub, а если его там нет — из первого
заголовка внутри файла; в fb2 это `<title>` секции. Каким уровнем он записан
в книге, неважно: `h4` в начале главы — всё равно её название.

### Ссылки внутри книги

Оглавление в аннотации, сноски, перекрёстные ссылки — всё это остаётся рабочим.
Адрес из файла в разметку при этом не попадает: каждой цели выдаётся номер,
и наружу уходит только `<a href="#a12">` с `<span id="a12"></span>` в цели.
Один и тот же адрес всегда получает один номер, поэтому ссылка вперёд работает
наравне со ссылкой назад, а в epub — и через файл (`href="ch2.xhtml#top"`
попадает в `id="top"` внутри `ch2.xhtml`).

Цель ставится отдельным пустым элементом, а не атрибутом на соседнем теге:
якорь в книге может стоять на чём угодно, в том числе на теге, который мы
выкидываем. На вёрстку это не влияет — пустой inline не создаёт строки.

Наружу ссылок нет вовсе: в fb2 берутся только адреса с решётки, в epub —
только без двоеточия (двоеточие есть у любой схемы — `http:`, `mailto:`,
`javascript:` — и не встречается в относительном адресе файла). Текст ссылки
при этом остаётся на месте, пропадает только сама ссылка.

Тело `<body name="notes">` в fb2 раньше выкидывалось как «не текст книги» —
теперь это обычные главы в конце. Иначе каждая сноска вела бы в никуда.

`lang` нужен читалке для переносов: без него `hyphens: auto` не знает словаря
и в узкой колонке текст рвётся огромными пробелами.

## `.rda` — книги из R

На GitHub книги нередко лежат как данные R: репозиторий
[bradleyboehmke/harrypotter](https://github.com/bradleyboehmke/harrypotter)
хранит семь книг символьными векторами, по элементу на главу.

Крейта под RData для Rust нет, поэтому в `src/rda.rs` разобрано нужное
подмножество формата: снять сжатие (gzip / bzip2 / xz — какое именно, видно
по сигнатуре, расширение об этом молчит), пройти сериализацию XDR и достать
первый строковый вектор.

**Хранится это как fb2.** Конвертация происходит один раз на входе
(`store_book`), и дальше книга ничем не отличается от остальных: та же читалка,
тот же поиск, тот же разбор метаданных. Третий формат во всём остальном коде
не заводится — поддерживать его везде дороже, чем конвертировать однажды.

Название берётся из имени файла (`philosophers_stone.rda` → «Philosophers
Stone»): внутри `.rda` лежат голые данные, названия там нет. Абзацы режутся
не только по `\n`: в тех же книгах про Гарри Поттера переводов строк нет
вовсе, абзацы разделены идеографическими пробелами U+3000.

Ограничения на всякий случай стоят и здесь: 128 МБ на распакованное (сжатие
у `.rda` отличное, и безобидный файл может развернуться в гигабайты), 100 000
строк в векторе, 32 МБ на строку.

## «Мои книги» — полка, а не список загруженного

Библиотека общая, поэтому «моя книга» и «книга, которую я принёс» — разные вещи:
чужую книгу хочется отложить себе, а свою убрать из раздела, не удаляя её
из библиотеки. Отсюда отдельная таблица `shelf (user_id, book_id)`:

| | что решает |
|---|---|
| `shelf` | что читатель видит в разделе «Мои книги» (`mine` в ответе) |
| `books.owner_id` | кто книгу принёс: источник и право удалить (`canDelete`) |

Полка приезжает тем же запросом, что и книги: `left join shelf s on s.book_id =
b.id and s.user_id = $1`, поэтому `$1` в `BOOK_FROM` всегда читатель, а слова
поиска начинаются со второго плейсхолдера.

Загруженная книга ложится на полку сразу, в той же транзакции: откладывать себе
только что добавленную книгу — лишний шаг. Повторное добавление не ошибка
(`on conflict do nothing`), удаление отсутствующего — тоже: кнопку могли нажать
дважды или из двух окон.

Убрать с полки ≠ удалить: это разные эндпоинты, и подтверждения просит только
второй. Проверяет разницу тест `shelf_and_ownership_are_separate` — на полке
может лежать чужая книга, а своя может на ней не лежать.

## Источник вместо «кем добавлено»

`books.source_url` заполнен только у книг из внешних источников. Отсюда одно
понятие на два случая: в графе «Источник» стоит либо читатель, который принёс
файл, либо хост, откуда книгу забрали, — и во втором случае это ссылка на
страницу книги. `owner_id` остаётся и продолжает решать права: удалить может
тот, кто принёс, неважно, файлом или по ссылке.

## Что происходит с загруженной книгой

Файл приходит от кого угодно, поэтому до вставки в БД он проходит три проверки
(`src/books.rs::put_new_one`, `src/parse.rs`):

1. **Формат.** Принимаются только `BOOK_EXTS` — `epub`, `fb2` и `rda`. Во фронте
   тот же список стоит в `accept` файлового поля, но проверка на сервере
   не зависит от него: запрос ничего не стоит послать мимо формы.
2. **Содержимое.** Расширение — заявление клиента, а не факт. Настоящая проверка
   в том, что файл разбирается: `.epub`, внутри которого не zip, и `.fb2` без
   блока `<description>` отлетают с 400.
3. **Очистка метаданных.** `Meta::sanitized` — единственная дверь, через которую
   название, автор, дата, язык и аннотация попадают в БД:
   - вырезаются `\0` (Postgres такой символ в `text` не хранит вообще — без
     чистки это была бы ошибка 500) и прочие управляющие символы, кроме `\n`/`\t`;
   - вырезаются символы разворота текста (U+202E и соседи) — ими название
     в списке маскируют под что-то другое;
   - поля обрезаются по длине (аннотация 4000 символов, название 300), чтобы
     чужой файл не раздувал таблицу и не заставлял `/getAll` отдавать это всем;
   - пустое после чистки название превращается в `Untitled`, пустые поля — в `null`.

**Про SQL-инъекции.** Их здесь нет по построению, а не по бдительности: sqlx
отправляет значения отдельно от текста запроса (`.bind`), сервер БД никогда не
разбирает их как SQL. Единственный `format!` в запросах подставляет константы
`BOOK_COLS`/`BOOK_FROM`, пользовательских данных в нём нет. Название вида
`Robert'); DROP TABLE books;--` просто сохранится как название.

XSS тоже не проходит: React экранирует текст сам, а единственное место
с `dangerouslySetInnerHTML` — читалка, и разметку для неё собирает сервер
из своих тегов (см. «Читалку» выше). Данные из файла попадают туда только
экранированным текстом.

## Миграция данных

```sh
npm i mongoose pg argon2 @aws-sdk/client-s3
MONGO=... DATABASE_URL=... S3_BUCKET=... node migrate-from-mongo.js --dry-run
MONGO=... DATABASE_URL=... S3_BUCKET=... node migrate-from-mongo.js
```

Пароли из Mongo хешируются на лету. Файлы книг переносятся из S3 в `book_files`;
из бакета только читаем, ничего не удаляя, — откат это `truncate books cascade`.
Скрипт одноразовый, после переноса удалить вместе с его npm-зависимостями.
